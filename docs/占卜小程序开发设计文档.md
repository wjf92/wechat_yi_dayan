# 占卜微信小程序 · 开发设计文档

> 副标题：大衍筮法数字化 · 圆球代蓍草 · 划线分堆 · 挂一强制分步  
> 算法依据：刘君祖《易断全书》「占卜玄机」章（见同目录《占卜玄机.md》）  
> 文档版本：v1.0　|　状态：设计稿（待评审）

---

## 1. 项目概述

### 1.1 背景与目标

传统大衍筮法需用 50 根蓍草、历经「十八变」方成一卦，过程繁复、易出错，初学者往往望而却步。本项目将这一仪式数字化为**微信小程序**，核心目标：

- 用**一个个圆球**代替蓍草，视觉直观、操作轻盈；
- 保留仪式感与「人定随机」的精髓——**分二（分成左右两堆）由用户亲手划线完成**，确保随机性来自使用者本身，而非程序伪随机；
- **挂一**由程序自动完成，但作为**独立且不可跳过的步骤**呈现，强制用户点击「下一步」确认，既降低操作负担，又完整保留「分二→挂一→揲四→归奇」的礼序；
- 每一爻算完即**记入顶部六爻记录带**（爻位＋数字＋爻画），六爻齐备后**自动生成卦象**（含卦名、卦辞，及老阳/老阴变爻产生的「之卦」）。

### 1.2 目标用户

- 易学爱好者、研读《易经》/《易断全书》的读者；
- 想体验传统筮法、但被蓍草操作劝退的普通用户；
- 教学/演示场景（课堂、读书会展示「大衍之数」）。

### 1.3 设计原则

| 原则 | 说明 |
|---|---|
| 仪式感 | 每步有说明、有过渡，不让用户「一键成卦」，保留「十八变」的庄重 |
| 人控随机 | 唯一随机来源是用户划线分堆的位置，程序不替用户决定分堆 |
| 不可跳步 | 挂一虽自动，但必须用户确认「下一步」才推进，杜绝漏序 |
| 可追溯 | 每爻的数字、三变过程、最终卦象均可回看与本地保存 |
| 轻量 | 纯前端 + 本地存储即可运行，无需登录/云后端（见 §5、§6） |

## 2. 核心算法：大衍筮法建模

### 2.1 数学过程（三变）

准备：50 策 → 抽 1 策不用（象征太极，全程不参与）→ **49 策入局**。

每一爻需经 **3 次「变」**。每一次「变」的步骤与算式如下（其中 `L`=左堆、`R`=右堆，且 `L+R=N`）：

1. **分二**：用户划线将 `N` 策分成左右两堆（随机）。
2. **挂一**：从右堆取 1 策挂起（程序自动）。右堆余 `R−1`。
3. **揲四（右）**：将 `R−1` 每 4 个一数，余数 `r₁ = (R−1) mod 4`，整除则记 `4`。`r₁ ∈ {1,2,3,4}`。
4. **归奇（右）**：将 `r₁` 策置于指间（桌面）——**取出离席**；整除记四时，那四策同样要拿出来。
5. **再揲四（左）**：左堆 `L` 每 4 个一数（**此步不再挂一**），余数 `r₂ = L mod 4`，整除则记 `4`。`r₂ ∈ {1,2,3,4}`。
6. **再归奇（左）**：将 `r₂` 置于指间——同样取出离席。
7. **剩余** `= N − 1(挂) − r₁ − r₂`。

> **分界怎么算：只看球心**。每颗球归左还是归右，程序判定的是**球心**相对你所画那条线的位置——球心在线的左侧即为左堆，在右侧即为右堆。为什么不用「整颗球在线的哪侧」：球是圆的，线从球阵中间穿过去，必然要从若干球身上压过（实测每副平均 4~5 颗球的球心距线不足一个半径），若要求「线不得碰球」，几乎每一副都无解，等于无法操作。
>
> 若球心正好落在线上（横向偏差 ≤ 0.30R，约球径的 1/7），判据是「**严格小于归左**」，即**恰好相等时归右**——浮点运算下几乎不会真的取等，这条只作书面约定。实测约 **61% 的占例会遇上 1~3 颗**这样的球（平均 0.89 颗），程序会在球外加一圈**朱红虚环**把它们标出来，底栏同时写明「归属只看球心：心在线左即左，在线右即右」，让占者看得见它是怎么被算掉的，不至于误以为漏算或错算。
>
> **两端不必画到球阵之外**：你画的只是「分界的示意」，程序会把这一笔的两端沿切线延长到圆席之外（细虚线示之），再按延长后的分界判归属。所以收笔停在半途、或斜着画而从圆席侧边出界，都不影响判定——只要笔势是一个方向。

> 这类球**不拦截重画**：它们既非「线没画到头」，也非「回折」，只是恰好切在球心上；若也要求重画，六成占例都要被打回一次，而球阵排布固定、占者本就倾向把线从球与球之间穿过去，几乎无从避开。

> 注：因 `R−1 + L = N−1`，且两堆各以 4 除，余数和必为 4 或 8，故一变后剩余只可能是 `44` 或 `40`。
>
> **余数为 0 的处理（易错点）**：揲四若恰好整除，余数不作 `0`，而**记作 4**（「若整除，不是余数为零，而是余数为四」）。故一变的归奇恒为 `1 + 4` 或 `1 + 8`，即 **5 或 9**；二、三变的归奇恒为 **4 或 8**。界面上此时会在算式旁标「整除者以四为余」，并且余数那一圈里就是整整四策，不是空圈。

> **这四策是「取出」，不是「记账」（球数账本）**：余数为 4 时，这四策与余 1/2/3 一样**离开席面**（原书图注即作「取出四根」；明伦刊本亦云「已經四四數過之策則放回」——放回的是数过的整组，余策则「扐」出）。**绝不能「球仍留在堆里、只在账上记个 4」**，两种做法在下一变的入席球数上立刻分叉：

| 变次 | 入席球数 | 本变离席（挂 1 ＋ 右余 ＋ 左余） | 下一变入席 |
|---|---|---|---|
| 第一变 | 49 | 5 或 9 | **44 / 40** |
| 第二变 | 44 或 40 | 4 或 8 | 40 / 36 / 32 |
| 第三变 | 40 / 36 / 32 | 4 或 8 | 36 / 32 / 28 / 24 → 9/8/7/6 |

> 穷举全部分堆可验算：按「取出」得 一变 40/44、三变 24/28/32/36（÷4 = 6/7/8/9）；若改成「整除的四策留在堆里、只记 4」，一变就会冒出 **48**，三变只剩 36/40（÷4 = 9/**10**）——10 不是爻数，卦就废了。所以 `next = N − 1 − r₁ − r₂` 里减掉的 `r₁`、`r₂` 必须是**真实离席的球数**，账与实必须相符：台面剩下多少球，下一变就进多少球。

### 2.2 三变累计与爻值映射

| 变次 | 入策 N | 出策（剩余）可能值 | 说明 |
|---|---|---|---|
| 第一变 | 49 | **44 / 40** | 余数和 4 或 8 |
| 第二变 | 44 或 40 | **40 / 36 / 32** | |
| 第三变 | 40 / 36 / 32 | **36 / 32 / 28 / 24** | 决定本爻 |

第三变剩余除以 4，得到本爻之「数」，并映射阴阳老少：

| 剩余策 | ÷4 | 数 | 爻性 | 爻象 | 是否可变 |
|---|---|---|---|---|---|
| 36 | 9 | **九** | 老阳 | ⚊ | 可变（阳极生阴） |
| 32 | 8 | **八** | 少阴 | ⚋ | 不变 |
| 28 | 7 | **七** | 少阳 | ⚊ | 不变 |
| 24 | 6 | **六** | 老阴 | ⚋ | 可变（阴极生阳） |

- 阳爻画 `⚊`，旁记「七/九」；阴爻画 `⚋`，旁记「八/六」。
- **六爻每爻三变，共十八变而成一卦**（「十有八变而成卦」）。

### 2.3 六爻成卦与变爻（之卦）

- 自下而上记六爻：**初、二、三、四、五、上**。
- 若六爻皆「七/八」（少阳/少阴），则**之卦 = 本卦**，按卦辞占（书中明夷例即是）。
- 若出现「九」（老阳）或「六」（老阴），该爻**发动**生变：九→阴、六→阳，由此得到**之卦（变卦）**。设计上需同时展示**本卦**与**之卦**及各自卦辞/爻辞。

### 2.4 算法伪代码

```text
function divinateOneYao():
  N = 49
  for bian in [1,2,3]:
      L, R = userDrawLineAndSplit(N)   // 用户划线分堆（人控随机）
      await confirmHangOne()           // 挂一自动完成，但须用户点「下一步」方可继续（不可跳过）
      r1 = mod4(R - 1)                 // 右堆揲四归奇
      r2 = mod4(L)                     // 左堆揲四归奇（不再挂一）
      N  = N - 1 - r1 - r2             // 本变剩余，作为下一变入策
  number = N / 4                       // 7/8/9/6
  return mapToYao(number)              // 阴阳老少 + 爻象

function mod4(x):
  return (x % 4 == 0) ? 4 : (x % 4)

// 主流程
yaos = []
for i in [初,二,三,四,五,上]:
    yaos.append(divinateOneYao())      // 每爻算完在下方记录数字
hexagram = buildHexagram(yaos)         // 自动生成卦象
showResult(hexagram)                   // 本卦 +（若有变爻）之卦
```

### 2.5 校验要点（确定性）

- `r₁`、`r₂` 取值必为 1–4；**整除时记 4，绝不记 0**（关键易错点）。
- 每变出策必等于 `N − 1 − r₁ − r₂`；**入席球数逐变递减**（49 → 44/40 → 40/36/32 → 36/32/28/24），台面球数恒等于该变的出策数——不允许「归奇之策还留在堆里」。
- 第三变剩余必 ∈ {24,28,32,36}，÷4 必得整数 6/7/8/9。
- 用户分堆后，程序用 `L+R` 校验是否等于当前 `N`，防止界面/计算不一致。

## 3. 产品功能设计

### 3.1 用户主流程

```
起卦页(提示心念所问之事→开始)
   │
   ▼
[循环 6 次 · 每爻皆八步，各爻开场重演 S1 挂一]
   │
   ├─ S1 挂一       —— 五十取一、虚而不用，黑球飞入顶部常驻栏 →【下一步】(强制，不可跳过)
   ├─ S2 分二挂一   —— 用户划线分堆 + 右堆取一枚变黑挂起 →【下一步】
   ├─ S3 揲四归奇   —— 原席就地画圈（四策一圈、圈不相交），余策变黑飞入右柱 →【下一步】(余策洗牌)
   ├─ S4 分二挂一   —— 第二变(44 策，洗牌后重新划线)
   ├─ S5 揲四归奇   —— 第二变(余 36，同法归柱)
   ├─ S6 分二挂一   —— 第三变(36 策，洗牌后重新划线)
   ├─ S7 揲四归奇   —— 第三变(余 28，同法归柱)
   └─ S8 成爻       —— 28 ÷ 4 ＝ 7，记入顶部六爻记录带的「初」位
   │
   ▼
卦象结果页 —— 六爻齐备自动生成卦象 + 卦名/卦辞（+ 之卦）
```

### 3.2 分步交互详述

| 步 | 名称 | 输入方 | 界面要素 | 推进条件 | 可否跳过 |
|---|---|---|---|---|---|
| S1 | **挂一** | 程序自动 | **每爻开场**：圆席重新列满**五十策**，顶部太极栏回到**淡虚位**（无黑球、标「待拈」）；点「下一步」后最上一策变黑、离席**如日初升般缓缓升入顶部太极栏**（**2.0s**，带朱金日晕），此策在**本爻三变**内不动，席上存 49 策；成爻页清席后演下一爻会再重演一次 | **必须点「下一步」** | **不可（强制确认）** |
| S2/S4/S6 | **分二挂一** | 用户 ＋ 程序 | 圆席 + 划线手势 + 自动挂一 + 左右/挂/合 计数 | 划线成功即自动挂一，再点「下一步」 | 不可（未划线不能进） |
| S3/S5/S7 | **揲四归奇** | 程序自动 | **不换页面、球一颗不动**：手绘的那条分堆线原样留在席上；四策就近聚成一撮，用**手绘感的闭合圈**就地圈起（圈线＝四策球心的最小生成树骨架等距外扩，遇别策与划线处收口；**硬下限**保证四策各自整颗落在圈内，宁可圈圈稍稍相蹭也不把球切在外）；余数一撮单独一圈（实线加粗、淡底），球变黑后**飞入右侧三变柱**（柱内「挂一 1 ｜ 右余 ｜ 左余」三段之间留空当）+ 算式 `49 − 1 − r₁ − r₂ ＝ 44`（v21 起与说明文字同款淡灰字，不再是黑底卡片） | 点「下一步」 | 不可（展示后确认） |
| S8 | **成爻** | — | 余策 ÷ 4 ＝ 爻数（六/七/八/九）＋爻象＋变爻标记，落入**顶部六爻记录带**的「初」位 | 点「看卦象结果」 | 不可 |
| — | **卦象生成** | 程序自动 | 六爻纵向卦象 + 卦名/卦辞 | 自动 | — |

**挂一「不可跳过」的实现（门禁）：** S1 进入时**只列五十策、太极仍是虚位**，「五十取一」这一动作由用户点「下一步」亲自触发（**v18「如日初升」，v19 调速为 2.0s**：变黑凝住 420ms → 飞球硬起始帧 160ms → 露头浮起 260ms → 缓缓升空 1000ms → 落定 160ms，合计 2000ms），动画收尾才置 `taiji = true` 并推进 S2；不点绝不自动取、绝不自动前进。分二挂一（S2/S4/S6）中的挂一则在划线松手后自动完成，同样必须再点一次「下一步」才进入揲四——两步都保留礼序，不因自动化而省略。

**演下一爻（v16）：** 成爻页 `enterYao()` 会清空球堆；点「演下一爻」时 `onNext()` 令 `yaoIndex+1`、`taiji=false`、`hangAnimating=false` 后调用 `enterHang()`（旧版是 `buildSteps(false)` + `enterSplit(0)`，因太极已立而不再铺球，遂留下空席）。`enterHang()` 重铺 50 策、重置八步轨／三变柱／墨迹、太极位设回虚位、按钮回到「下一步·拈出太极」，所以新的一爻不会空席、不会跳过挂一按钮，太极球也不会一进新爻就瞬间出现在太极位——同一段 2.0s 的「如日初升」动画每爻完整重播。

**v20 追加的跨爻防线：** v16 之后仍收到「演下一爻是空白」的反馈，逐帧复核显示逻辑层在 WebView 派生版里稳定（点击后 0／80／200／400／700／1100／1600／2200／2900ms 采样全是 50 策，无一帧被清空），故补两道与渲染引擎无关的结构性保险：① `later()` 为每个延时回调绑定 `this.epoch`，`enterHang()` 开场 `clearTimeout` 清空上一爻全部挂起回调并递增代次，任何迟到的归奇／洗牌／挂一动画回调自动作废，不会再抹掉刚铺好的球堆或越过挂一推进到分二；② `enterHang()` 收尾用 `later(...,30)` 做**幂等校验**，`this.balls` 或 `this.data.balls` 不是 50 策就补铺一次——专门兜住小程序原生渲染器把「成爻清空 → 新爻铺满」两次 `setData` 安排在同一帧时 `wx:for` key 复用停在空列表的情形。故意注入「上一爻迟到回调」的对抗测试证实：二爻全程 50 策、挂一步、按钮正确，旧回调被完全隔离。若真机仍见空席，优先排查**是否加载了旧编译**（`project.config.json` 的 `compileHotReLoad:false`，须手动点「编译」或重新生成预览码；APK 须覆盖安装新包）。

### 3.3 强制分步状态机（单爻内）

```
HANG ──next(强制)──▶ SPLIT ──draw+auto-hang──▶ COUNT ──next──▶ SPLIT ──▶ COUNT
                       ▲                                            │
                       └──────────── 三变循环 ──────────────────────┘
                                                                    ▼
                                                              YAO_DONE ──next──▶ 下一爻 / HEXAGRAM
```

单爻固定 **8 步**：`hang → split(变1) → count(变1) → split(变2) → count(变2) → split(变3) → count(变3) → yao`。任何一步都不会自动跳转，`step` 仅由用户点击推进；分二步骤额外要求「已划线」才能推进。

六爻间：`YAO_DONE ──next──▶ (下一爻)HANG`，第六爻完成后 `YAO_DONE ──▶ HEXAGRAM`。

### 6.3 关键组件

- **circle-field**：圆形筮席（直径 380rpx），内以「最小间距 + 碰撞检测」散列 `N` 个空心白球；用户划线后按线左右分配 `L/R`，并自动从右堆取一挂起（黑球入挂区、原位留虚圈）。
- **step-rail**：**圆席下方的横排步骤轨**（六爻每爻 8 点＋连接线），已完成描黑、当前项反白放大；**轨上方一行「S2 分二挂一 · 第1变」全称说明，28rpx 墨黑加粗**。移至下方后，圆席得以横向占满，直径从 168 放大到约 224（小程序 500rpx）。
- **pillar-board**：右侧三变柱（一变/二变/三变），**柱内以黑色小球自上而下逐颗堆放**，颗数＝本变归奇之策＝挂一 1 ＋ 右堆余数 r₂ ＋ 左堆余数 r₁（一变为 5 或 9，二、三变为 4 或 8）。**自上而下依次是挂一 ／ 右余 ／ 左余**，三段之间留固定空当；柱顶标总数，**柱下不再另注算式**。
- **yao-record**：**顶部六个记录格**（初→上），每成一爻填入「七 ⚊」这类数字＋爻画，当前爻朱红高亮；与顶部进度圆点合并为同一条，避免上下重复。
- **hexagram-view**：自下而上六爻（初在最下），画阴阳爻线，标注老/少与九/六，老爻用朱红描边提示「变」。

### 6.4 分堆交互实现要点

- 圆球以绝对坐标布局，记录每球中心 `(x,y)`。
- 用户 `touchmove` 形成折线/直线，取近似竖直线 `x = x_line`；`x < x_line` 归左堆，否则归右堆。
- 实时显示 `L`、`R` 计数；`L+R` 必须等于 `N`，否则提示重画。
- **划线合法性**：判定在 `utils/dayan.js` 的 `checkSplit()`，松手时先验笔势再分堆——
  1. `short`：这一笔总长不足两个球径，看不出方向；
  2. `flat`：近乎水平（y 跨度不足球阵高度的三成）。判定是按高度取分界点的 x，横线没有高下之分；
  3. `back`：中途回折超过 1.5 个球径，同一高度会有两个分界点，判无效。
  说明一：**不拦「线擦到球」**——49 策密排时任何贯穿线都必然擦到某颗球（实测最近球心距 0.49 个球径），拦它会让人根本画不过去；球归哪边一律按其**球心**在线之左右判定。
  说明二：**不要求线画到球阵之外**（2026-11-06 改）。旧版有 `span` 一条：线首尾必须盖过最上一排与最下一排球心，否则判「最下面 N 策落在线外」。斜着画时线常常先从圆席侧边出界、y 没到底（用户截图即此），明明已经把球分成两堆却被判无效。现改为两端沿切线**自动延长到席外**（`extendSplit()`，取端点与内侧第 4 点的方向，外推到圆席矩形边界 +2%），延长线照样把圆席切开，归属按延长后的分界判；两段延长线在画布上以**细虚线**（alpha 0.42、线宽 1.0u）画出，超过席高 5% 才显示，免得画到底时多出小尾巴。
- 为兼顾手感，允许划线略斜，按每球到线的水平投影判定归属。

### 6.5 挂一「不可跳过」实现

```js
// divine.js 片段：一爻八步，任何一步都不自动跳转
data: { step: 0 }            // 0..7 → S1..S8

onLoad() { this.enterHang() }            // S1：进屏即已「五十取一」

onNext() {
  const st = STEPS[this.data.step]
  if (st.k === 'hang')  return this.enterSplit(0)      // S1 → S2（须点按钮）
  if (st.k === 'split') {
    if (!this.data.splitDone) return wx.showToast(...)  // 未划线不可推进
    return this.enterCount(st.b)                        // S2 → S3
  }
  if (st.k === 'count') {
    return st.b < 2 ? this.enterSplit(st.b + 1) : this.enterYao()
  }
  /* S8 成爻之后 → 下一爻 / 卦象 */
}

// 划线松手：分二 + 自动挂一在同一屏内完成，但仍须再点「下一步」
onTouchEnd() {
  const res = dayan.splitByCurve(balls, samples, sz)
  this.pendingChange = dayan.change(total, res.left)    // 得 r₁/r₂/余策
  this.setData({ splitDone: true, btnText: '下 一 步' })
}
```

> 关键点：S1 进入时「挂一」已由程序算完，但 **`step` 停在 0 不前进**；分二挂一中的挂一也在松手时自动完成，同样必须再点一次「下一步」。两处都做到「自动完成却不可跳过」。

### 6.6 揲四「手绘圈」的几何（2026-11-06 两次修正）

每撮（4 策，余数撮 1~4 策）在 `utils/loops.js` 的 `loopGeom()` 里生成一条闭合曲线，画在 `#ink` 画布上：

1. **团块**＝组内球心的最小生成树骨架胶囊 ∪ 四颗球盘，逐方向取径向最外点，得 `must`（硬下限＝球边再外 1.25u）与 `want`（常态留白＝2.05u）；
2. **闭运算**（`closeSeq`，滚动最大 → 滚动最小，窗口 12 个方向 / 余数撮 20）：把「窄而深」的球缝深谷抬平，宽缓的腰身保留 —— 这一步专治尖刺、直角与「狗啃」的凹口；
3. **与凸包混合**：同方向再算「球心凸包外扩」（支撑函数 `max(p_i·u)+d`），取 `0.84×胶囊 + 0.16×凸包`。凸包是凸曲线，权重虽小，足以把两颗球之间的「外公切线」这段死直边拉成浅弧，圈于是圆润而不生硬；权重再大就会撑开去圈邻球（实测 0.72 时别组球心被误圈 0.9%，0.84 时 0.6%）；
4. 遇别组球（`foreignCap`，留 1.0u）、遇你画的线（`wallFor`，留 1.2u）收口，**收口不许越过 `must`**；
5. 144 个方向采样 → 2 轮极轻平滑（顶回 `must`，凸化的 `must` 不会震荡出鼓包）→ 按弧长重采成 56 点 → 3 轮「邻点均值 + 撞下限顶回」；
6. 圈间互让 `avoidCross()`（包围盒预筛），同样以 `must` 为下限——宁可两圈稍稍相蹭，也不把球漏在圈外。

**修正记录一（v11）**：旧版只按「各球圆盘并集取径向最外沿」，四颗一散开时球缝那条射线谁也碰不到，半径从 100+ px 掉到个位数，圈于是甩出尖刺斜穿自家球——实测 **17.4% 的球被切在圈外**。

**修正记录二（v14）**：MST 骨架虽保住了「不漏球」，但球缝处的径向深谷仍在，圈被啃成花生形、手套形、靴子形（截图里的灰底余数圈尤甚）。加第 2、3 步（闭运算 + 凸包混合）后回归 200 副 / 7253 颗球：

| 指标 | v11（骨架） | v14（闭运算+混合） |
|---|---|---|
| 平均凸度（圈面积 / 其凸包面积） | 0.864（最凹 0.70） | **0.959**（最凹 0.94） |
| 余数撮的圈 | 靴子形 | **0.99**（近正圆角凸形） |
| 漏圈自家球 | 0 | 0（最小净空 1.8px） |
| 每圈圈住的球数 | 3.71 | 3.68 |
| 别组球心被误圈 | 0.05% | 0.6% |
| 圈互穿 | 0.3% | 2.0% |
| `buildLoops()` 单次 | 20ms | **12.8ms** |

后两项是「圆润」的代价：密排时任何包住四颗球的圈都会与邻圈相蹭，压到 0 就等于回到花生形。取舍原则是**宁可两圈相蹭、偶尔框进邻球，也不让圈啃出尖角**。

| 取走处 | 被挂起的那一策**原地变为黑球**（右堆最上一枚），与「挂 1 策·太极」框中的黑球互相印证；黑球被拎起那刻，原位立刻收成**虚线小圈**，不留实球残影 |
| 分二分隔 | 用户手绘的线**原样保留**（保留全部采样点，不简化、不拉直、不替换为直线），松手后**按这条线的走向**把球划归左右两堆；线两侧各出「左 n / 右 m」角标 |
| 揲四 | **球位一律不动**：沿用分二那一步的散乱落点，不重排、不聚拢、不换页面；四策就近聚成一撮，用**手绘感的闭合圈**就地圈出——圈线取「四策球心的最小生成树骨架 + 等距外扩」，遇别组球、遇你画的那条线即收口；**收口只许发生在硬下限之外**（球边再外 1.6u），因此**四策必被整颗圈住**，极端拥挤处两圈可稍稍相蹭、圈在球堆边缘可微越线；余数那一撮单独一圈（实线加粗、淡底），圈内正好是这些策 |
| 归奇动画 | 变黑后的黑球**逐颗飞向右侧柱内对应格位**（起点为该球原位，`cubic-bezier(.45,.05,.25,1)`，错峰 32ms），落定即收成柱内那颗实心小黑点（`scale≈0.34`）；原位上黑球「被拎走」的一瞬收成虚线小圈，表示已扐出、只计数。**手绘圈与划线在这一步仍然保留**，不在归奇结束时消失，等点「下一步」洗牌时才与球的位移同步（520ms）一并淡去。**整除记四的那四策同样离席飞走**——柱内实到颗数＝本变离席数（5/9 或 4/8），席上剩下的球数＝下一变入席数 |
| 洗牌 | 一变既毕，余策球**错峰 7ms/颗**缓缓挪到新落点（520ms）；新落点同样走 `layoutEven`，**密度与上一变一致**，不会越洗越稀；原位的虚线小圈此时抹掉 |
| 版面结构 | 顶部六爻记录带（初→上，兼作进度）｜**放大版「挂 1 策·太极」栏**（46rpx 黑球＋呼吸虚线环＋「不动」朱红签；**太极未立时**为淡虚线圈＋「五十策列席／待拈」）｜中央圆形筮席（**596rpx，占屏宽 79.5%**；小屏按可用高度自动回收，下限 400rpx），**席外左上角常驻「在席 N 策」标签**｜右侧三根「一变/二变/三变」柱（112rpx）｜其下**先一行「S3 揲四归奇 · 第1变」步名（28rpx 加粗墨黑），再是步骤轨**｜**步骤轨下紧接朱红主按钮**，按钮下方才依次是说明文字／计数 chip／算式／门禁提示／重新划线（v21：主操作上移、信息下移） |
| 三变柱 | **不复用柱高**：柱内以**实心黑球**自上而下逐颗表示归奇之策（12rpx，自上而下＝挂 1 ／ 右余 ／ 左余），数值标在柱顶；未到的变显示「—」与空柱；段与段之间留 12rpx 空当；柱下不注算式 |
| 席上策数 | 圆席**外左上角**一枚白底墨边小标签「在席 **N** 策」，N 为席上实际未离席之策（归奇变 `ghost` 的虚线圈不计）；随分二 / 揲四 / 成爻实时变化，让「五十取一、三变递减」一眼可数 |
| 起卦意象 | 起卦页以「一堆空心白球中 1 颗黑球带虚线箭头飞出」呼应原书图①「拈出一枚不用／大衍之数五十，其用四十有九」；演卦页 S1 即以此动画实拍：五十策中拈出一枚飞入太极虚位 |
| 字体 | 现代无衬线（苹方/思源黑体），标题字重加大 |
| 卦象 | 阴阳爻以粗横线表示（墨黑），阴爻中断为两截；老阳/老阴变爻以朱红描边强调「变」 |
| 按钮 | 主按钮朱红实心；**紧接步骤轨下方**（`.dbot` 首元素，`margin-top:0`，与步骤条相隔 18rpx），所有说明文字、chip、算式、门禁提示一律在其下；「下一步」在挂一屏加大并标注「此步不可跳过」 |
| 动效 | 挂一「飞出 1 策（黑球）」微动画；分堆后球**不重排、不位移**，仅按线归属左右，保持「线在哪里、堆就在哪里」的现场感；划线完成只重绘线、标签与按钮，**球一颗都不重摆**（同一步重绘时跳过一切定位） |

## 8. 原型设计说明（对应原型图）

原型见同目录 **`占卜小程序原型.html`**（手机框 + 屏幕切换器，**白底墨黑极简风**，版式：顶部六爻记录带 · 挂一常驻栏 · 中央大圆席 · 右侧三变黑球柱 · 下方八步横排步骤轨 · 底部算式与按钮），共 4 个主视图 + 单爻 8 步可逐屏查看（步骤条支持直接跳转，连续点击时带完整动画）：

1. **起卦页** — 顶部「一堆白球中 1 颗黑球带虚线箭头飞出」呼应原书「拈出一枚不用」；仪式性提示「心念所问之事」（不提供输入框）、开始起卦。
2. **演卦 · 一爻八步**（同一页面内 8 个状态；六爻每爻都从 S1 起，均为 8 步）：
   - **S1 挂一** — 圆席先散列**五十策**、太极栏为虚位；点「下一步」才把最上一策拈黑、飞到顶部「挂一 · 太极之策」栏，席上余四十九策；此策在本爻三变内不动；纯确认步，不点「下一步」绝不前进。演下一爻时重新铺席、太极回虚位，动画再完整播一遍。
   - **S2/S4/S6 分二挂一** — 在圆席上手绘划线分成左右两堆：**画成什么形状就保留什么形状**，不会拉直；松手后按这条线把球划归左右（**球一颗都不位移**），并自右堆拈最上一枚变黑挂起；底部四枚计数：左 / 右 / 挂 1 / 合，另有「重新划线」可重来。若线把右堆切到不足两策（挂一后无从揲四）或左堆为空，会拦下并要求重画。
   - **S3/S5/S7 揲四归奇** — **不再另开页面、球也不动**：你画的那条线仍在，席上直接浮出一个个**手绘感的圈**（每圈四策，遇别策与划线处收口；硬下限保证四策整颗在圈内；余数那一撮单独实线加粗、淡底），余策变黑后逐颗飞向右侧对应柱段，空掉的圈随之淡出；底部算式按原书图注写法给出 `49 − 1(挂) − 1(右余) − 3(左余) ＝ 44`（v21 起为淡灰说明文字，无黑底卡片），整除时另标「整除者以四为余」。
   - **S8 成爻** — 圆席内呈现 `28 ÷ 4 ＝ 七` 与阳爻爻线，数字（六/七/八/九）与爻画落入**顶部六爻记录带**的「初」位；若为九或六，格上另标「变」字。
3. **卦象结果** — 六爻卦象 + 卦名（朱红印章）+ 卦辞（+ 之卦）。
4. **流程与状态机** — 一爻八步流程图与 `HANG→SPLIT→COUNT→…→YAO_DONE` 状态机。

### 8.1 小程序同步现状（`dayan-miniprogram`）

`pages/divine` 已按本文件 v7 口径重写，与原型对齐：

| 项 | 小程序实现 |
|---|---|
| 划线后球不动 | 划线只重绘画布（`paint()`），球数组不动；同一步重绘不触发重摆 |
| 四策手绘圈 | 几何抽到 `utils/loops.js`（纯函数）：`groupBalls` 聚簇 → `loopGeom` 取四球圆盘并集外沿、被别组球/划线收口 → `avoidCross` → Catmull-Rom **三次贝塞尔** |
| 画布 | `<canvas type="2d" id="ink">` 同层渲染覆盖圆席（`z-index:5`），一笔宽随球径等比缩放（`u = sz/13`）；余数圈实线 1.4u + 淡底，普通圈虚线 `3.4u/3.2u` |
| 手绘圈淡入淡出 | 每圈独立 alpha，`inkTick()` 33ms 一帧缓动，错峰 55ms |
| 余策飞入柱 | 页面级 `position:fixed` 飞球层，起点取圆席 `boundingClientRect` + 球心，终点按 `.pil-dots` **自上而下**逐格对齐（格距 16rpx，段间 +8rpx；挂 1 在第 0 格、右余 1..r₁、左余 r₁+1..r₁+r₂），`transition-delay` 32ms 错峰；**落定后 `scale` 收到 0.34 收成柱内实心小黑点** |
| 洗牌重分 | 下一变 `relayout()` 复用存活球，落点由 `layoutEven`（螺旋＋松弛）给出，`transition-duration:520ms` + 7ms/颗 错峰 |
| 三变柱三段 | 柱内**实心黑球**自上而下按「挂 1 ｜ 右余 ｜ 左余」渲染，段间 `.bdot.gap` 留空当；柱顶标总数 |
| 球数账本 | `relayout()` 先滤掉 `cls` 为 `gone/ghost` 的球，保证 49→44/40→…→24 逐变递减，不「复活」 |
| 太极栏 | 顶部「挂 1 策 · 太极」栏（放大版：46rpx 黑球 + 呼吸虚线环 + 「不动」签）；**每爻起筮时先回虚位**（`taijiOn:false`），由该爻 S1 的拈出动画重新落入，非「一次取定、全程常驻」；`buildSteps(true)` 六爻每爻皆 8 步 |
| 太极拈出动画 | `takeTaiji()`：**总时长 2.0s**（v19 调速；五段常量集中在函数顶部，改这一组即可整体调速）。起筮铺 **50 策**、太极位为虚位（`taijiOn:false`）；点「下一步」→ 最上一策 260ms 渐变为黑并 `scale(1.26)` 抬起（`.ball.dark.pick`），**凝住 420ms** 看清取的是哪一颗 → 撤去原位并起一枚**同位置同大小同色同缩放**的 `position:fixed` 黑飞球，挂 `.sun` 并以 `d:0` 硬渲染起始帧（160ms）→ **露头**：先垂直浮起 16px（260ms）→ **升空**：以 `cubic-bezier(.34,.02,.22,1)` 用 1000ms 慢起缓停飞到 `.tj-ball` 球心（`measure()` 量视口坐标，`sc=46rpx/sz`）→ 160ms 后落定，同瞬 `taijiOn:true`，接缝不可见；收尾置 `taiji=true` 并进入 S2。**六爻每爻各播一次**。四拍各是一次独立 `setData`、间隔 ≥160ms，不靠「两次 setData 的差值」撑 transition 起点；动画期间 `hangAnimating` + `btnWait` 双锁防连点 |
| 日出观感（v18，v19 同步调速） | `.flyball.sun` 由三组 keyframes 独立承担光感：`sunBody`／`sunGlow` 各 **1600ms**（＝飞球出现到落定的 1580ms）、`sunRim` **1200ms**，让墨色日轮镀暖金边、朱金日晕自球心铺开（α 0→0.93→0）、荡出两道细金日冕环；落定时 `.taiji.on .tj-ring::after` 的 `sunLand`（**700ms**）再向外扩散一圈暖光，`.tj-ball` 显形改为 **0.2s** 缓放、不再弹跳。光感走 keyframes 而非 transition，即使某次 `setData` 在真机上被合并、位移没播出来，由暗转明的完整过程依然可见 |
| 席上策数 | 圆席**外左上角**「在席 N 策」标签，由 `renderBalls()` 现算 `this.balls` 中非 `ghost/gone` 的球数，随每一步自动更新：50 →（拈出太极）49 → 每变归奇后 `ch.next` → 成爻 0 → 下一爻重新 50 → 49；左右角标下移到 `top:58rpx` 避开它 |
| 球数账本（补充） | S1 从 50 颗里 `splice` 掉一枚后不再重铺，保留其余 49 颗原落点（避免整席跳动）；`enterSplit(0)` 仅在**席上策数 ≠ 49** 时补铺一次 `relayout(49,false)`，正常流程不触发；`this.sz` 沿用 50 策的球径，分二/揲四几何仍自洽 |
| 球堆不闪 | 开局 `relayout(50,false)` 不再给球挂 `pop` 入场动画（原先非动画重铺也带 `pop`，列表一旦重排就会把「从无到有」的淡入集体重播，即「闪无又闪现」）；挂一落定后 `takeTaiji`/`enterSplit(0)` 均不再 `setData({balls})`，实测落定后球节点 49 颗全部保留、零重建 |
| Android 派生版「闪现」根因（v18） | `tools/runtime.js` 的 keyed diff 原先对**每个匹配到的节点都无条件 `appendChild`**；把已在文档中的节点再 append 会 detach/attach，浏览器随之重置 CSS transition 与 animation。实测真实时间采样：位移 x 从 0 直接跳到 −208（无中间值），日晕透明度反复从头重播——这就是「一眨眼就到太极位」的真因，与时长无关。现改为**仅当成员/顺序真的变化时才挪动节点**；修复后 x 连续采样出 0→−3.5→−22.9→−64.4→−112.1→−147.7→−187.6→−208 共 12 个中间值，日晕 α 连续 16 档。此修复同时让归奇飞柱、洗牌位移等所有 transition 类动画恢复正常 |
| 演下一爻 | `onNext()` 成爻分支：`yaoIndex+=1` → `taiji=false` → `hangAnimating=false` → `enterHang()`（重铺 50 策、八步轨、三变柱、墨迹、`taijiOn:false`、按钮「下一步·拈出太极」）。修复旧版直接 `buildSteps(false)` + `enterSplit(0)` 造成的**空席、缺挂一按钮、太极瞬间到位**三处问题；实测二爻开局 50 策／8 步轨／太极虚位，动画落定后 49 策进分二 |
| 跨爻回调隔离（v20） | `later(fn,ms)` 统一绑定 `this.epoch`；`enterHang()` 开场 `clearTimeout` 清掉上一爻挂起的归奇／洗牌／标红／飞球回调并 `epoch+=1`，迟到回调一律 `return`，不再改写新爻界面。`enterHang()` 收尾 `later(...,30)` 幂等校验：席上非 50 策即 `relayout(50,false)` 补铺，兜住小程序同一帧合并两次 `setData` 导致 `wx:for` 停在空列表的情形。对抗测试（人为注入迟到清空回调）显示二爻 0～1600ms 始终 50 策、`stepKey=hang`、按钮「下一步·拈出太极」，JS 错误 0 |
| 记录带 | 真实爻值（六/七/八/九）＋爻画，九六右上角标「变」 |
| 算式 | `49 － 1(挂) － r₁(右余) － r₂(左余) ＝ 44`，下方补「本变归奇 N 策」与「整除者以四为余」；仅 `stepKey==='count'` 时出现，位于按钮下方 |
| 底部布局（v21） | `divine.wxml` 的 `.dbot` 顺序改为 **按钮 → `.dhint` 说明 → `.chips` → `.formula` → `.lock` → `.relink`**；`.formula` 去掉 `background:#15171c`／18rpx 圆角／14rpx 内边距，改为透明底、`padding:0`、`border-radius:0`，三行文字用与 `.dhint` 同一套灰字（`.f-eq` 20rpx `#71767f`，标题与脚注 18rpx `#9aa0aa`），不再有突兀的大黑块；`.btn` 的 `margin-top` 归零，靠 `.dbot` 的 18rpx 与步骤条留白 |

## 10. 风险与注意事项

1. **随机性真实性**：分堆必须由用户手势决定，不可改用 `Math.random` 替用户分堆（违背「人定随机」原则）。
2. **整除记 4**：`mod4` 务必把整除映射为 4，否则剩余策数错误、爻值失真——已写入 §2.5 校验。
3. **64 卦查表完整性**：结果页依赖完整 64 卦（名/辞/爻辞）数据，需核对无误；老阴老阳变爻须正确生成之卦。
4. **挂一门禁**：不可为「省步骤」而自动跳过挂一确认，产品明确要求保留此礼序。
5. **性能**：49 圆球 + 触摸事件在低端机需保证流畅，建议用 `canvas` 或限制 DOM 圆球数（可分堆后再用计数代替逐球渲染）。
6. **合规**：占卜类小程序需注意微信平台对「占卜/算命」类目的类目资质与审核口径，上线前确认类目与文案合规。
